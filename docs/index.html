Local DNS-over-HTTPS filter for Windows

DNS filtering decided by a quorum, not by one provider.

Your browser sends its DNS queries to a small server on your own computer (127.0.0.1). For each domain it asks several independent filtering DNS providers in parallel and blocks the domain if any one of them says block. One compromised or mistaken provider can't let a threat through on its own.

Download from GitHub Source code

Pre-release. Windows 10 (version 2004) or later, x64. Free and open source, Apache 2.0. Not in Microsoft Store yet.

What it is, and what it isn't

A DNS-level filter

Malware, phishing, ads, trackers and (if you turn it on) adult content, blocked by domain name before a connection starts.

Not an ad blocker extension

No element picker, no cosmetic filtering. It works alongside uBlock Origin or a similar extension rather than replacing it.

Browsers only

It filters browsers you point at it. Other apps keep using the system DNS: the system-wide setting is left alone on purpose, so a crash can't take your whole network down.

Open to audit

Every claim on this page can be checked in the code, the design spec and the test suite on GitHub.

How filtering works

Each query goes through the same checks, top to bottom. The first one that gives a final answer wins; the rest are skipped.

  1. Your allow list. Listed domains are always allowed.
  2. Your block list, plus optional public block lists (ads, trackers, threats; off by default). Blocked without any network request.
  3. Country domain zones you chose to block, such as a whole .xx zone.
  4. Cache. A domain checked recently is answered from memory.
  5. Popular sites only (optional, off by default): domains outside the zones you picked are blocked.
  6. The quorum. The enabled providers are asked in parallel. If any one says block, the domain is blocked. Out of the box: Quad9, Cloudflare (malware) and AdGuard DNS; you can change the list.
  7. Country check (optional): an allowed answer whose IP address is in a country you blocked is blocked too.

A blocked domain resolves to 0.0.0.0 / ::, never to “no such domain”: some browsers treat “no such domain” as a reason to quietly ask another resolver, which would skip the filter.

Trade-offs, stated up front

Several providers see your queries

To get a quorum, every query not in the cache goes to each enabled provider and to an unfiltered reference resolver. More third parties see which domains you visit, in exchange for wider threat coverage. The settings page shows exactly who they are. See the privacy policy.

A certificate for 127.0.0.1 only

Browsers only talk DNS-over-HTTPS to a trusted server, so the app installs a self-signed certificate valid for 127.0.0.1 alone. It is deliberately not a certificate authority: a stolen key could imitate this local server, not other websites.

When filters can't be reached

By default the app lets the answer through rather than breaking your browsing, and the tray icon and settings page tell you that filtering is degraded. You can switch to failing closed instead.

Install

Each release on the Releases page has an MSIX package. It is test-signed for now, so Windows needs its certificate trusted once. A helper script does that and installs the package.

  1. Download dns-quorum-filter.msix, dns-quorum-filter.cer and Trust-TestCert.ps1 into one folder.
  2. In that folder, run: 
    powershell -ExecutionPolicy Bypass -File .\Trust-TestCert.ps1 -Install
    It asks for administrator rights, trusts the package certificate and installs the app. Read the script first if you like: it is short and plain PowerShell.
  3. Start DNS Quorum Filter from the Start menu once. Windows only registers it to start with Windows after that first launch.
  4. The first-run wizard offers to trust the local certificate for 127.0.0.1. Accept it, then connect your browser (next section).

Before uninstalling, use the tray menu → Remove everything. Windows runs no app code when an MSIX package is removed, so the local certificate and the stored keys have to be cleaned up first.

Connect a browser

Set the browser's secure DNS (DNS-over-HTTPS) to a custom provider with this address (8443 is the default port): 

https://127.0.0.1:8443/dns-query

The app's settings page shows the same steps for the browser you open it in, with a copy button.

Chrome

chrome://settings/security → Use secure DNS → Custom.

Edge

edge://settings/privacy/security → Use secure DNS → Choose a service provider. If the switch is grey with a briefcase icon, Edge thinks it is managed by an organisation and won't let you change it; edge://policy lists the policies.

Brave

brave://settings/security → Use secure DNS (already on) → Add custom provider.

Opera

opera://settings/system → turn on “Use DNS-over-HTTPS instead of the system's DNS settings” → the last, unnamed item with a text field.

Vivaldi

vivaldi:settings/network/ → DNS over HTTPS → Other DNS provider. A green tick means Vivaldi accepted the address.

Firefox

about:preferences#privacy → DNS over HTTPS → Max Protection only → Choose provider → Custom. In “Increased Protection” Firefox quietly falls back to the system DNS for every blocked site, so the site opens anyway.

LibreWolf

Not supported: it doesn't trust certificates from the Windows certificate store.

If a website asks to access “other apps and services on this device”, choose Block.

With that permission a site could send requests to the local service: guess from response times which sites you opened recently, and add lines to its log. Without it, all five browsers we tested (Chrome, Edge, Brave, Opera, Firefox) refuse such requests.

Check that it works

  1. Open the settings page, https://127.0.0.1:8443/admin/ui, directly. The status at the top says whether filtering is on, and when the browser last sent a query.
  2. Add a harmless domain to your block list there and open it. Chromium browsers show ERR_ADDRESS_INVALID, Firefox shows “Hmm. We're having trouble finding that site.” The log shows the same domain as blocked at that moment.
  3. Remove the domain from the block list again.

Known limitations

  • Windows only for now. macOS and Linux are planned.
  • Only browsers set up as above are filtered.
  • Firefox must use Max Protection; LibreWolf is not supported.
  • The package is test-signed until the Microsoft Store release.
  • The interface is in 37 languages; 35 of them are machine translations not yet reviewed by native speakers.

The full, technical list is in KNOWN-LIMITATIONS.md.
