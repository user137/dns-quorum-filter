# Задачі

Формат: `- [ ] T-N — опис (розділ SPEC.md, якщо застосовно)`. Нумерація наскрізна
через увесь файл (не по фазах), нові задачі отримують наступний вільний номер.
Завершені задачі переносяться в [`TASKS-DONE.md`](TASKS-DONE.md), не видаляються.

UI-задачі нижче (T-47, T-52 та ін.) мають детальні таблиці полів/DTO/мокап у
[`UI-SPEC.md`](UI-SPEC.md) — звірити перед імплементацією.

Формулювання "дзеркальні до TS discriminated union" також застаріле — вже покрито загальною приміткою SPEC.md §8 (T-149, "Tauri-вікно замінено треєм + вбудованим веб-UI"), майбутній споживач — plain-JS log-екран, не TypeScript. Блокується появою log-екрану/endpoint'у (суміжно з T-46/T-47, окремого номера ще немає).
- [ ] T-56 — Індикатор стану: чи браузер використовує локальний DoH, чи фільтрація активна, деградовані апстріми, окремий стан "фільтрацію вимкнено — 0 voters" (8, 3.3, 8.1) — `dnsqb-tray`'s tooltip (T-149) — простіший 3-станний попередник, не заміна: без перевірки браузера/watchdog/degraded, ціль лишається веб-UI чи повноцінному майбутньому екрану. **T-134 (SPEC.md Відкриті питання п.10) дала кандидатну, але неперевірену техніку** для "браузер не використовує локальний DoH": активний canary-запит із `/admin/ui` — потребує нового, ще не спроєктованого механізму прив'язки домену до фіксованої IP (override-список сьогодні вміє лише Allow/Block, не довільну відповідь) і окремого empirical scratch-прогону перед довірою, не готовий план імплементації.
- [ ] T-58 — Тести UI↔бекенд каналу за 4 категоріями: smoke, злам/exploit, misuse, fuzz (`proptest`) (8.1) — **звужено** (CLAUDE.md, "Фаза 1, twenty-third slice"): два з трьох misuse-прикладів закриті реальним фіксом + тестом, не лише тестом — необмежений розмір `overrides.toml`/`resolver_config.toml` (`OverrideError::TooLarge`/`ConfigError::TooLarge`, bounded read замість read-then-check) і "rapid toggle race" (`AppState::persist_lock`, емпірично підтверджений реальний баг — 16/20 провалів без фіксу, 20/20 успіхів із фіксом); allow+block конфлікт лишається окремо покритим деінде (не цією задачею). Перший реальний прохід `proptest` у workspace — три властивості на найбільш зовнішніх межах парсингу каналу (`parse_pattern`, `wire_bytes_from_get`, `serve()` проти довільного `/admin/config` тіла), явно **не** вичерпний: інші admin-маршрути й `/dns-query`'s POST-тіло самі не фаззяться цього разу — залишковий ґеп, не прихований.
