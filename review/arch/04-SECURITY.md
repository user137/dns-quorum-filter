## 2. Сертифікат і секрети

`ВИМІРЯНО (MSIX-installed)`, `openssl x509 -noout -text` на `cert.pem`: ECDSA P-256, **Basic
Constraints: critical, CA:FALSE**, SAN = `127.0.0.1`, `::1`, `localhost`, термін дії 2020–2120
(сто років — свідоме рішення, `cert.rs:35`, тест `generated_cert_uses_the_stated_hundred_year…`).
Лист, не CA — як вимагає SPEC §2, і це видно з самого сертифіката, а не лише з коду. Приватний
ключ — у Credential Manager (`key_store`), не на диску. Ротація потребує ручного рестарту служби
(задокументовано). 4 записи секретів; тести засмічують справжнє сховище — T-265.

## 3. Приватність

- **Сервісні логи:** `ВИМІРЯНО (MSIX-installed)` — `dnsqb-service.log`, 628 рядків за ~2,5 год:
  доменоподібних токенів, крім `docs.rs` (текст помилки hyper) та `index.html`, немає.
  `grep tracing!` з аргументами domain/host/qname по трьох крейтах — лише імена маркер-файлів.
  Відомі вектори закрито: `UpstreamError` (T-200), текст помилки `toml` — T-252 (хвиля 7).
- **Fan-out як видимий компроміс:** картка фільтрів показує «Кожен запит поза кешем …: N перевірок
  + резервний резолвер» (`uk.json` `filterControls.fanoutSummary`). Вимогу SPEC виконано.
- **Фонові запити:** проби `reachability` + DoH-sentinel до baseline — задокументовано
  (CLAUDE.md, рядок `reachability`). Обсяги — Фаза 6.
- **Персист журналу й персональної зони:** опційний, шифрований, окремий ключ для персональної
  зони — добре.

## 4. Знахідки

```
[ARCH-14] severity: minor (→ major, якщо експеримент підтвердить на браузері за замовчуванням)
Де: crates/dnsqb-service/src/dispatch.rs (обробник `GET /dns-query`, без перевірки Origin /
  Sec-Fetch-Site); dispatch.rs:1384–1389 (`record_personal_visit` на кожен запит)
Категорія: безпека
Джерело: ВИМІРЯНО (MSIX-installed, curl, 3 запити `www.example.org`): промах 0.155 с,
  попадання 0.032 / 0.033 с (з TLS-рукостисканням) — різниця ≈120 мс, вимірюється тривіально.
  Що браузер пропустить такий запит з публічної сторінки — ГІПОТЕЗА.
Три Б: software | user (приватність)
Кому шкодить (аудиторія): людина відкриває будь-яку сторінку з вбудованим скриптом (реклама,
  трекер). Скрипт робить `fetch('https://127.0.0.1:8443/dns-query?dns=…', {mode:'no-cors'})` —
  GET без preflight; сертифікат довірений (майстер встановив його в `CurrentUser\Root`), тож TLS
  проходить. За часом відповіді скрипт дізнається, чи був домен у кеші, тобто **чи відвідувала
  людина сайт X упродовж TTL** — історія переглядів, яку проєкт якраз обіцяє не розкривати.
  Побічно: (1) якщо персональна зона ввімкнена, кожен такий запит записується як «візит»
  (`record_personal_visit`) — сторінка, відкрита кілька днів поспіль, може «навчити» зону
  довільному домену й послабити рейтинг-фільтр для нього (не форс-дозвіл — кворум усе одно
  біжить); (2) кожен такий запит — fan-out до N провайдерів від імені користувача. Людина цього
  не помітить ніяк.
Що: `/dns-query` приймає GET від будь-кого на loopback. Справжні DoH-запити браузера йдуть із
  мережевого стеку браузера, а не з контексту сторінки; запити сторінок несуть `Origin` та/або
  `Sec-Fetch-Site: cross-site`. Сучасні Chromium-браузери впроваджують обмеження Private/Local
  Network Access для запитів «публічний сайт → loopback» (ЗАГАЛЬНА ПРАКТИКА — точний статус у
  поточних Chrome/Edge/Brave і відсутність у Firefox **не перевірено**). SECURITY.md моделює
  CSRF-запис і DNS-rebinding, але не читання через таймінг.
Варіанти:
  (а) відхиляти `/dns-query`, якщо запит несе `Origin` або `Sec-Fetch-Site` зі значенням не
      `none`/`same-origin` (внутрішні DoH-запити браузера цих заголовків, імовірно, не мають —
      **перевірити** на Chrome/Firefox/Edge перед увімкненням, інакше зламаємо сам фільтр);
      дешево, одна перевірка + тест.
  (б) нічого не міняти в коді, але задокументувати в SECURITY.md як прийнятий ризик із
      посиланням на LNA-захист браузерів.
  (в) не чіпати.
Рекомендація: спершу експеримент (одна сесія): з `https://example.org` у Chrome і Firefox
  виконати no-cors fetch на `/dns-query` і (1) подивитися, чи дійшов він до служби (рядок журналу
  для тестового домену), (2) які заголовки несе внутрішній DoH-запит браузера (лог заголовків на
  скретч-інстансі). Якщо (1) так і (2) без `Sec-Fetch-Site` — (а); інакше (б).
Тест / вимір: юніт `serve`: GET `/dns-query` з `Sec-Fetch-Site: cross-site` → 403; без
  заголовка → 200; наживо — експеримент вище.
Перевірка «вже відомо»: grep `timing|cache.{0,20}prob|side.channel|Private Network Access|
  Local Network Access|cross-site|cross-origin` у SPEC/SECURITY/KNOWN-LIMITATIONS/DECISIONS/
  TASKS — лише рядок SECURITY.md:62 про CSRF-запис. Не зафіксовано.
```

## 5. Ланцюг постачання

- `cargo audit` + `cargo deny check` — блокувальний джоб `audit` у `ci.yml`; останні прогони на
  `main` — `success` (`gh run list`, CI).

  macOS-гілка. `aws-lc-sys` — єдина C-криптоповерхня, прийнятий ризик у SECURITY.md (T-213).
- Відтворювана збірка — блокувальний джоб `repro` (T-100).
- Підпис релізу — `test-signed` ефемерним сертифікатом; користувач довіряє `.cer` у
  `LocalMachine\TrustedPeople` (PowerShell, UAC). Це **довіра до ключа, якого вже не існує**
  (ефемерний) — безпечна, але кожен реліз — новий `.cer` і новий UAC; закривається T-239.
