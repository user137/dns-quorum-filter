## КОНТЕКСТ ПРОЄКТУ (фактичний, не з README)

Локальний DoH-сервер + quorum-резолвер під Windows. Rust workspace,
три крейти:

| Крейт | Тип | Роль (уточнити з коду у Фазі 0) |
|---|---|---|
| `dnsqb-service` | `lib` + `[[bin]]` | DoH-лістенер на `127.0.0.1`, quorum-резолвер, `/admin/*` HTTP + вбудована веб-панель (`include_str!`), GeoIP, rating-filter, watchdog-халфи |
| `dnsqb-watcher` | `[[bin]]`, ~340 LOC | watchdog-процес (SPEC.md §7), єдиний писар `watchdog-state.json` |
| `dnsqb-tray` | `[[bin]]`, ~2.2k LOC | tray-іконка, lifecycle-актуатор; залежить від `dnsqb-service` як lib лише заради `AdminClient` |

**Це НЕ vibe-coded прототип із неявними рішеннями.** Проєкт має:
`SPEC.md` (2100+ рядків, §-нумерація) — джерело істини для дизайну;
`DECISIONS.md` — ретро-виправлення прийнятих рішень, перекриває SPEC.md
за датою; `TASKS.md` / `TASKS-DONE.md` — беклог і історія задач;
`CLAUDE.md` — агентський конспект із розділом «Known limitations in
shipped code» (це вже наявний каталог знахідок) і довгим списком
`Rust/tooling gotchas`; `DECISIONS.md` + advisor-гейти на обох кінцях
більшості батчів; 300+ комітів.

Три Б (три опори безпеки) — власна рамка проєкту, вживай її по імені:
- **User safety** — чи лишає режим збою користувача в гіршому стані, ніж
  повна відсутність фільтрації, і чи він це помітить.
- **Software safety** — чи безпечний код проти ворожого/спотвореного
  вводу, доказово з самого рядка. Дві межі вводу: DNS wire від апстрімів
  і `/admin/*` HTTP від tray/браузера.
- **Lower-layer safety** — кожен шар, який проєкт не контролює (OS trust
  store, апстрім-DoH, GeoIP/top-N фіди, DoH-fallback браузера), —
  недовірений.

## ЖОРСТКІ ПРАВИЛА

### Правило 0 — перевір, чи це вже вирішено, ПЕРЕД тим як назвати знахідкою
Перед кожною знахідкою: grep `SPEC.md` за § (пайплайн §5.3, quorum §3,
cert §2, cache §4, override-списки §5, лог §6, watchdog §7, UI §8,
наскрізні вимоги §"Наскрізні вимоги", ризики §"Відкриті питання"),
`DECISIONS.md` за датою, `CLAUDE.md` розділ «Known limitations in
shipped code», `TASKS.md`. Знахідка валідна лише якщо:
(а) ніде не зафіксована, (б) суперечить зафіксованому, або
(в) саме́ зафіксоване обґрунтування хибне — тоді цитуй його й скажи чому.
Інакше це `already-filed` — одним рядком із посиланням, не окремим блоком.

### Правило 1 — жодного твердження про код, який ти не прочитав
Спочатку Read/Grep, потім висновок. Не читав — пиши «не перевірено».

### Правило 2 — класифікуй джерело твердження
`ПІДТВЕРДЖЕНО В КОДІ` (з `file:line`) / `ГІПОТЕЗА` (треба перевірити X) /
`ЗАГАЛЬНА ПРАКТИКА` (знання, не про цей репо) /
`ВЖЕ ЗАФІКСОВАНО` (з `file` + § або датою).

### Правило 3 — не вигадуй назви крейтів, API, версій, CVE
Не впевнений — `cargo tree`, `cargo metadata`, docs.rs, або «не знаю».
`deny.toml` пінить граф до `x86_64-pc-windows-msvc`; фічі крейтів
підібрані вручну (`default-features = false`), тож `--all-features`
НЕ вживати — воно зʼєднає фіча-сети, яких проєкт свідомо уникає.

### Правило 4 — класифікуй severity чесно
`blocker` (ламається зараз на реальних даних) / `major` / `minor` /
`nit` / `already-filed`. Категорія: баг коректності / ризик безпеки /
архітектурний борг / неоптимізовано / справа смаку. «Неідіоматично» —
не баг. Не роздувай severity. Прототип ≠ продакшн: кажучи «не витримає»,
уточнюй ЧОГО саме — навантаження, збою, ворожого вводу, часу.

### Правило 5 — не хвали код, щоб пом'якшити критику
Модуль зроблений добре — одне речення, чому саме. Без мотиваційного.

### Правило 6 — локальний прогін ≠ CI
Хост розробки — `x86_64-pc-windows-gnu`; CI — `windows-latest` / MSVC.
Кожен записаний baseline мусить казати, ДЕ він прогнаний. T-50 —
власний шрам проєкту саме на цьому (локально зелено, на CI-раннері
червоно через інші дефолтні ACL).

### Правило 7 — одна фаза = одна сесія
Не забігай уперед. Наприкінці фази — звіт у файл, резюме в чат
(≤10 рядків), і STOP до мого явного «далі» / «Продовжуй».

### Правило 8 — мова українська
Код, імена, команди, цитати — як в оригіналі.

### Фаза 2 — Коректність і безпека  (рамка: Три Б)
- **`unsafe`**: first-party `unsafe` = 0 (`#![forbid(unsafe_code)]` на
  всіх трьох кореневих + service `main.rs` — підтвердити одним рядком).
  Замість порожньої множини — vendored-FFI поверхня
  (`windows-native-keyring-store`, `chacha20`/`poly1305` SIMD,
  `ntapi`/`windows-*` через `sysinfo`, `aws-lc-sys`): чи containment-
  твердження в `SECURITY.md` досі істинне. Miri — `N/A` (див. вище).
- **panic-поверхня** (поза test-модулями, з grep: `watchdog/instance.rs`
  ~13, `tls.rs` 2, `quorum.rs` 1, `main.rs` 1): `#![deny(unwrap_used,
  expect_used)]` вже ввімкнено, тож кожен — або в `#[cfg(windows)]`
  шелі, або дозволений свідомо. Перевірити кожен, не рахувати.
  Плюс індексація зрізів, арифметика на зовнішніх числах (TTL, розміри,
  CIDR-префікси — CLAUDE.md має гочу про `<< 32` overflow)
- **модель помилок**: `thiserror` скрізь (не `anyhow` у lib). Помилки
  проковтуються? `let _ =` / `.ok()` / `Err(_) => {}` без коментаря-
  чому? `?` губить контекст?
- **async**: блокуючі виклики в async (спавн `certutil`, файлові
  синхронні читання — CLAUDE.md згадує T-160 синхронний `.mmdb` на
  старті), lock через `.await`, cancellation safety (є гоча про
  доказ скасування через `start_paused` + near-zero elapsed),
  unbounded-канали, витік task'ів
- **конкурентність**: `RwLock<Arc<T>>` патерн (читач клонує Arc, не
  тримає lock через `.await`) — де порушено; deadlock-порядки;
  `persist_lock` cross-field-read дисципліна (рекурентний баг-клас
  T-57/T-139/T-149/T-47/T-77 — перевірити кожен писар
  `resolver_config.toml`)
- **довіра до вводу** (Software safety): `/admin/*` хендлери, DNS wire,
  файли, конфіг, top-N/GeoIP архіви (bounded decompress? integrity
  gate до свопу?). Хто може надіслати і що при ворожому вмісті. SSRF
  на custom provider URL (CLAUDE.md: literal-host only — вже зафіксовано)
- **authn/authz веб-панелі**: `application/json` CSRF-гейт на write-
  роутах, `127.0.0.1`-only bind, `dispatch::ROUTES` allowlist — хто
  реально має доступ до керування; чи гейт на КОЖНОМУ write-роуті
- **приватність (наскрізна вимога — окремий підрозділ)**: доменні
  імена НЕ в діагностичних/сервісних логах. Відомі вектори витоку —
  чек-ліст: `reqwest::Error` Display містить base64url-запит (= домен);
  `toml::de::Error` Display/Debug друкує рядок `overrides.toml`;
  `ProtoError` повідомлення. Query-log — in-memory ring buffer за
  замовч.; персист опційний + шифрований
- **ресурси**: файли, сокети, процеси, тимчасові файли, atomic-write
  (`write_atomic` = temp + `sync_all` + `rename`), зупинка/дренаж
Вихід: `review/02-CORRECTNESS.md`.

### Фаза 3 — Архітектура і відповідність місії
- для кожного модуля: робить те, що обіцяє іменем, чи більше
- зв'язність і зачеплення; де бізнес-логіка протекла в транспорт
  (`dispatch.rs` ~8.5k рядків — кандидат, але **спочатку розділити
  прод/тест LOC**, інакше твердження нефальсифіковне) або в UI
- контракти між трьома крейтами: версіонування (`persist_dto`
  `PersistedFileV1`, `encrypted_file` header version, `watchdog-state.json`
  §7.1 #7), сумісність, що при частковому оновленні (tray нової версії +
  service старої)
- стан: де живе, хто власник, що при рестарті/краші (§7.1 #7 «watcher —
  єдиний писар», budget не durable у напрямку service→watcher — вже
  зафіксовано; `fail_closed` timeout-Block в памʼяті переживає outage —
  вже зафіксовано)
- конфіг і секрети: `resolver_config.toml` / `overrides.toml`, OS
  secret store (`keyring`) — 3 записи; валідація, дефолти, hard-cutover
  без dual-format shim (зафіксований патерн)
- спостережуваність: `logging` модуль (файлові логи, фіксований INFO,
  без `env-filter`) — чи достатньо, щоб діагностувати збій без дебагера,
  не порушивши приватність
- десктопна інтеграція: MSIX (немає uninstall-хука → in-app
  `local_state::remove_all` + `self_uninstall.rs`), автозапуск
  (`windows.startupTask`), права (`CurrentUser\Root` trust store,
  `TrustedPeople` для MSIX-підпису), видалення
- познач для кожного пункту: неможливо виправити без переписування /
  дорого / незручно / не проблема для PET-масштабу
Вихід: `review/03-ARCH.md`.
