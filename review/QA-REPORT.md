## Знахідки за серйозністю

**User safety — користувач може лишитись без фільтра й не знати про це:**

- **T-257** — Firefox у режимі «Посилений захист» (TRR 2) обходить фільтр на кожному
  блокуванні: тихий fallback на системний DNS.
- **T-243** — автозапуску немає, доки застосунок не запустили хоча б раз (задокументована
  поведінка Microsoft для `desktop:StartupTask`) — одна підтверджена причина; чи пояснює вона
  початковий баг-репорт, не перевірено (питання користувачу нижче).
- **T-266** — після `GaveUp` порада трею «open the app» не працює; швидкий перезапуск
  watcher-а успадковує `GaveUp` при робочій службі, і нагляд вимкнено.
- **T-254** — hero `/admin/ui` показує «Захищено», коли жоден фільтр не відповідає.
- **T-244** — апгрейд MSIX документованим шляхом мовчки не спрацьовує.
- **T-261** — Edge з будь-якою політикою організації не дає ввімкнути Secure DNS.

**Security / software safety:**

- **T-256** — поля `[cache]` без верхньої межі; значення біля `u64::MAX` панікують на
  гарячому шляху.
- **Хвиля 0** — аудит ін'єкцій у полях API (запит користувача, задача ще без номера).

**Функціональні й UX:**

## Потрібні рішення користувача

1. **T-243** — спершу відповідь: чи був застосунок запущений хоч раз до того ребуту, після
   якого не стартував? Далі — інструкція «після встановлення запустіть застосунок один раз»
   і/або `rescap5:ImmediateRegistration` для Store-збірки (custom capability від Microsoft).
2. **T-266** — що саме скидає `GaveUp`: запуск плитки, пункт трею, чи щось інше; і текст
   tooltip під цей шлях.
3. **T-268** — перейменувати кнопку `/admin/ui`, чи зробити її рівнозначною пункту трею.
4. **T-260** — ручний вибір браузера в картці підключення (Vivaldi за UA не відрізнити від
   Chrome).
5. **T-254** — дизайн hero при мертвих фільтрах (у плані позначено «лише після рішення»).
6. **Хвиля 0** — старт виправлень з аудиту ін'єкцій, кожна хвиля за окремим «так».

## Що лишилось неперевіреним

- **Мертвий DoH в Opera і Vivaldi** (`I-opera-dead-doh`, `I-vivaldi-dead-doh`). Тимчасові
  профілі MCP зникли після ребуту, а `vivaldi-devtools` після нього не стартує. Поведінку
  Chromium на мертвому DoH показав Brave (жорстка відмова, без fallback).
- **Видалення: звіт-діалог і відповідь маршруту.** Друге натискання danger-zone, «Повністю
  видалити» в треї і деінсталяцію виконав користувач, бо класифікатор режиму auto Claude Code
  заборонив незворотне видалення. Кінцевий стан перевірено (`G-uninstall` PASS); самі вікна
  звіту — ні (`A-admin-uninstall-local-state-HP`, `B-danger-HP`, `C-REMOVE_ALL_ID-HP` —
  NOT RUN).
- **Шаблонні MF/EP-рядки трею й іконки** (подвійні натискання, швидка зміна станів, помилка
  під час дії) і стани, що потребують редагування `hosts` з UAC (`D-icon-Filtering-degraded-all*`).
- **`F-state-ChannelDegraded`** — при вбивстві служби всі три канали замовкають разом, проміжний
  стан не досягається.
- Повний перелік — рядки з вердиктом `NOT RUN` і `—` у матриці.
